# M0 闸门实测记录（真机结论，非预期）

> 记录 M0 技术闸门在这台开发机上的真实结果，供 M1 实现与验收引用。
> 全部为行为与结论描述，不含真实路径、账号或机器信息；示例路径一律用 `/path/to/project` 这类占位值。

## 1. 闸门 4：Snap Layouts 与自定义标题栏

### 1.1 已成立（自动化，可重复）

真实顶层窗口收到真实 `WM_NCHITTEST` 时：

- 客户区热区返回 `HTMAXBUTTON`；
- 标题栏热区返回 `HTMAXBUTTON`；
- 两处之外落回默认处理（客户区 `HTCLIENT`、标题栏 `HTCAPTION`）。

以上由 `tests/` 下的集成测试真起窗口、真发消息断言，不含模拟。

### 1.2 真机视觉结论（2026-10-25，本机，结论：不支持）

同一台机器、同一进程里的三次真机观察，每次均由用户本人将鼠标在目标位置停留 0.5 秒：

| 窗口 | 形态 | 最大化按钮由谁画 | 悬停是否弹出 Snap 面板 |
|---|---|---|---|
| A | 原生系统标题栏 | Windows | **弹出** |
| B | 系统标题栏 + 客户区自绘热区返回 `HTMAXBUTTON` | Windows 画按钮，应用谎报热区 | **不弹** |
| C | 无系统标题栏（客户区覆盖整个窗口）+ 客户区自绘热区返回 `HTMAXBUTTON` | 只有应用的热区 | **不弹** |

结论：

- 本机的 Snap 面板功能本身是好的（窗口 A 弹得出来），所以这不可能是「机器开关关着」。
- **应用自己指定最大化热区、返回 `HTMAXBUTTON` 这条路，在本机不触发面板**；有没有系统标题栏都不改变结果。
- 因此闸门 4 的视觉项判 **不通过**，按规格的回退条款处理：**Snap 面板不承诺**，但最小化 / 最大化 / 关闭三键必须全部可用。

### 1.4 实测结论（含未通过项）

1. **标题栏走「客户区上部自绘 + `WM_NCHITTEST`」**，不在非客户区硬画。原因：实测 `WM_NCPAINT` 自绘的标记在 DWM 下会被系统重绘盖掉（绘制后经一次窗口激活即消失），非客户区自绘不可靠。
2. **去掉系统标题栏不能靠删 `WS_CAPTION`**：实测请求去掉后，窗口实际样式里 caption 位仍然存在（`0x14CF0000`），系统把它加了回来。有效做法是处理 `WM_NCCALCSIZE` 并返回 0，让客户区覆盖整个窗口；实测该窗口的窗口尺寸与客户区尺寸相等、非客户区上边距为 0，画面上不再出现系统标题栏。
3. **Snap 面板：实测不支持，转为不承诺项**（见 §1.2）。最小化 / 最大化 / 关闭三键必须全可用，这一条不受 Snap 结论影响。

### 1.5 DPI 事实（会影响命中与验收）

- 本机显示缩放为 **150%**（`GetDpiForWindow` = 144）。
- 未声明 DPI 感知的进程读到的是**虚拟化坐标**：同一窗口在无感知进程里量到 655×437，在 Per-Monitor V2 进程里是 982×656。坐标类断言若混用两者，会假绿或假红。
- 因此 Host 进程必须显式声明 **Per-Monitor V2**；当前通过 `app.manifest` 声明，进程内自检读到的感知级别为 `PerMonitorAware`。

## 2. 闸门 2：子会话代理启动与自退

### 2.1 已成立（真机）

代理在主桌面会话被手动启动时：

- **158 ms 内退出**，退出码 **3**；
- 结构化日志写明命中哪道闸（`event` = `gate.console_session`，只含白名单字段）。

身份闸写成纯函数（`AgentSessionGate`）+ 真实 WTS 会话 ID，且与 `Process.SessionId` 交叉校验，避免 P/Invoke 写错导致「永远放行」。

### 2.2 前置条件（更正过的实测事实）

「RDP 连接自动拉起代理 → 代理在子会话内启动 explorer → 桌面完整」这一半**尚未验证**，但前置条件已经查清，且与最初的判断相反：

| 前置 | 实测状态 |
|---|---|
| 子会话能力是否开启 | **已开启**：`wtsapi32.dll` 的 `WTSIsChildSessionsEnabled` 返回 `true` |
| 该状态存在哪里 | **不在注册表**：`Terminal Server` 键下搜索 `ChildSession` 零命中，必须用 API 探测，读注册表会得出错误结论 |
| 开启/关闭所需权限 | **管理员**；非管理员调用会被系统拒绝（错误码 5），且改完立即生效，无需重启 |
| `fDenyTSConnections`（RDP 入站） | **0**；为 1 时不得连接，报专门错误码 |
| `fDenyChildConnections` | **0**；为 1 时不得连接，否则会接管并注销当前交互会话 |

产品要求（由上述事实推出）：启动时用 API 探测；未开启时**必须显式请求管理员授权**，不得静默失败、不得假装成功；只记录「是不是本次由我们开启」，只有我们开启的才在会话结束时关回；连接前必须确认 `fDenyChildConnections = 0`。

### 2.3 结论

闸门 2 的「代理拉起方式」定为 **RDP alternate shell**（连接设置只在内存里，注册表零落地）。`RunOnce` 方案在用户否决「登录启动注册」后不实现。代理身份闸已真机验证；其余部分等真机跑通后回填本节。
