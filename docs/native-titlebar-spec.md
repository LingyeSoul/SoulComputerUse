# 原生标题栏与窗口交互视觉规格（v1 · 供实现方实现 / 验收方验收）

> 范围：仅覆盖**主桌面原生窗口**的标题栏、关闭确认、状态呈现与黑边协调。
> 客户区只有虚拟桌面画面，本规格不涉及任何客户区 UI。
> 本文全部使用虚构占位值，不含真实路径、真实文件名、账户信息或截图数据。

## 0. 视觉方向（摘要）

把窗口做成一枚**克制的深色画框**：标题栏是一整条安静的信息带，桌面画面是唯一主角；状态全部用"一个色点 + 一行文字"表达，不弹横幅、不画进度条进客户区。黑边与标题栏同色温，让画面在聚焦时像浮在一整块深色哑光材质上，失焦时整框一起退灰，一眼可辨。

## 1. 硬约束

1. 标题栏用 **Win32/DWM 原生非客户区自绘**（`WM_NCPAINT` / `DwmExtendFrameIntoClientArea` + 自绘标题区），禁止网页 / Electron / 自绘控件伪标题栏。
2. 必须保留系统原生能力：Alt+F4、任务栏右键关闭、DPI 缩放、Win+方向键（系统 Snap）、Aero Shake 不强制但不得被破坏。**Snap Layouts 悬浮面板：最大化按钮的 `WM_NCHITTEST` 必须返回 `HTMAXBUTTON`，与 Microsoft 对自绘标题栏 Win32 应用的要求一致；该能力已由用户实测确认可用**（见 §6.3），最大化/还原行为本身也必须正常。
3. 客户区**只**渲染 RDP 桌面画面；除等比缩放黑边外，任何图标、文字、按钮、进度条都不得进入客户区。
4. 黑边（letterbox）永远是**纯黑 `#000000`**，属于画面容器的一部分，不承担任何状态语义。
5. 关闭必须二次确认；最小化、最大化/还原不做确认。
6. 标题栏三个按钮从左到右固定为：最小化、最大化/还原、关闭；**三键相邻、严丝合缝，关闭永远贴右缘**（v1.3 修订：原「关闭与另两键间留 1 个按钮宽间隔」作废——该空档不是按钮而是拖拽区，用户瞄着关闭点偏一格会把窗口拖走，是真实的点错陷阱，且不符合 Windows 平台三键相邻惯例）。
7. 状态呈现只许出现在标题栏（色点 + 文案 + 可选标题后缀），不许用客户区浮层。

## 2. Design tokens

所有尺寸以 **96 DPI = 1x** 为基准，运行时按系统 DPI 线性缩放；字号按系统文本缩放（Text Scale Factor）缩放。

默认跟随系统主题；任一主题下聚焦/失焦必须可区分。浅色主题为完整规格，深色为默认推荐。

| token | 深色·聚焦 | 深色·失焦 | 浅色·聚焦 | 浅色·失焦 |
|---|---|---|---|---|
| `titlebar.bg` | `#202124` | `#1B1C1E` | `#F3F3F3` | `#E8E8E8` |
| `titlebar.border` | `#000000` 1px | `#3A3B3E` 1px | `#D0D0D0` 1px | `#C4C4C4` 1px |
| `title.text` | `#FFFFFF` | `#9CA0A6`（6.55:1 实测） | `#1B1B1B` | `#686868`（4.55:1 实测） |
| `status.text` | `#C7C9CD` | `#7A7E84` | `#4A4A4A` | `#686868`（4.55:1 实测） |
| `icon.fg` | 同 `title.text` | 同 `title.text` | 同 `title.text` | 同 `title.text` |
| `caption.hover-bg` | `#38393D` | `#333438` | `#E5E5E5` | `#DEDEDE` |
| `caption.active-bg` | `#4A4B50` | `#424348` | `#D6D6D6` | `#CFCFCF` |
| `close.hover-bg` | `#C42B1C` | `#B3281A` | `#C42B1C` | `#B3281A` |
| `close.active-bg` | `#A72619` | `#9C2417` | `#A72619` | `#9C2417` |
| `caption.icon` | `#FFFFFF` | `#9CA0A6` | `#1B1B1B` | `#686868`（4.55:1 实测） |
| `close.hover-icon` | `#FFFFFF`（恒白） | 同左 | `#FFFFFF`（恒白） | 同左 |

规则说明：

- 聚焦/失焦的核心手段是**文字明度 + 下描边**：聚焦时标题栏与黑边之间一条更深的 `#000`（深色）/ 更实的 `#D0D0D0`（浅色）描边，失焦时描边变弱变亮。色点不随失焦退灰，保证状态仍可读。
- 关闭按钮 hover 永远用系统红 `#C42B1C` + 纯白图标，与 Win11 系统行为一致。
- 所有**文字**对比度 ≥ 4.5:1（含失焦档，正文标准；v1.2 修订，原 3:1 是图形线，不够）；色点与图标等**图形** ≥ 3:1。浅色失焦文字从 `#8A8A8A`（2.82:1 不达标）改深为 `#686868`（4.55:1 实测），`title.text` / `status.text` / `caption.icon` 三处同步；深色失焦 `#9CA0A6` 6.55:1 不动。

## 3. 标题栏布局

```
┌──────────────────────────────────────────────────────────────┐
│ [icon•] 标题文字 ─────(弹性留白)─────  ● 状态文字    _ □ ✕ │
└──────────────────────────────────────────────────────────────┘
 12px    8px                          ≥8px  8px       46 46 46（相邻，关闭贴右缘）
```

- 窗口图标：产品图标 16px；状态非 ready/idle 时，右下角叠 8px 状态点（外描 1px 标题栏底色）。
- 标题文字：模板 `产品名 — 子会话标签`，例：`SoulComputerUse — Session`。占位标签用虚构值 `example-session`，禁止真实会话 ID / 用户名进标题。
- 标题绘制三档口径（按 `TitleBounds` 宽度 `w` 判定，实现与验收统一）：
  - `w = 0`：**整段不画**（连省略号也不画），图标与状态区不受影响；
  - `0 < w < 全文本所需宽度`：**省略号截断**（`…`，尾部截断），tooltip 仍给全文本；
  - `w ≥ 全文本所需宽度`：完整绘制，不省略。
- 绘制必须按 `TitleBounds` 矩形裁剪，任何 DPI / 窗口尺寸 / 文本缩放下标题右缘**不得越过**按钮组左缘（§6.8 优先级），越过即缺陷。
- 状态区：状态点 + 状态文案（§4），靠右排列、左对齐，整组右缘距按钮组 8px。
- 最大化时按钮组不变；全屏（F11，若后续支持）时隐藏整条标题栏，鼠标移到屏幕顶部浮出。
- 还原态与最小化无关：最小化只隐藏窗口，标题栏状态保持不变。

## 4. 窗口状态在标题栏的呈现

| 状态 | 色点 | 标题栏文案 | 标题后缀 | 备注 |
|---|---|---|---|---|
| 启动中 `starting` | 灰 | `正在启动…` | 无 | transient，正常不出现超过数秒 |
| 等待验证 `awaiting_credentials` | 琥珀 | `等待验证 — 请在桌面窗口手动完成` | 无 | v1.6 实测定案（A）：**窗口内正在显示 Windows 系统登录界面，等待用户亲手登录**（2026-10-26 用户实测确认：先出现登录屏、输入密码后才进入桌面）。关闭流程每次注销子会话，所以**每一次全新会话开工都必经此档**，这就是「密码每次输入」的最终形态：凭据只进系统界面，应用与 agent 全程不接触凭据 |
| 连接中 `connecting` | 蓝 | `正在连接…` | 无 | 含代理握手 |
| 已就绪 `ready` | 绿 | 无文案，仅色点 | `— Session` | 就绪态最安静：只留绿点 |
| 断线 `disconnected` | 红 | `连接已断开` | 无 | 不自动重连时不附加文案 |
| 不支持 `blocked` | 紫 | 三选一文案，由状态机给定：①`不支持：UAC / 安全桌面，请人工处理` ②`不支持：非交互会话` ③`不支持：本机策略禁止子会话连接` | 无 | 文案全来自状态机枚举，标题栏只显示；③含策略值缺失被拒（fail-closed）与值非 0 被拒，具体操作指引走错误输出，标题栏只给结论 |
| 关闭中 `closing` | 灰 | `正在结束会话…` | 无 | 模态确认后的短暂态 |

- 状态文案全部来自状态机枚举，标题栏不做本地拼接，避免文案漂移。
- 空窗口列表、黑屏、抓帧失败等**不是**标题栏状态，不得借状态点表达。

### 4.1 门禁档位呈现（`awaiting_credentials` 专属）

门禁档位由 Core 在启动时探测，枚举名与契约 `authTier` 一一对应（三档），标题栏只渲染枚举结果，不写死任何设备名：

| `authTier` 枚举 | 标题栏短标注 | 呈现 |
|---|---|---|
| `hello-enrolled` | `请完成系统验证` | v1.7（对齐契约 v2.6）：恢复独立分支——开工时系统弹 Hello（PIN/指纹等，由 Windows 收，应用不碰凭据），标题栏呈琥珀等待 + 本短标注；`awaiting_credentials` 档的双重语义（Hello 开工验证 / 窗口内登录屏）共用同一主文案 |
| `system-credential` | 无 | v1.6 实测定案：**子会话系统登录验证**——应用不弹任何验证，全新子会话的 Windows 登录界面会出现在窗口内（`awaiting_credentials` 档），由用户亲手登录；这就是强验证，**不再称弱门禁** |
| `none` | `无法验证身份，已拒绝启动` | 仅在「即将拒启」且窗口已存在时出现：红色点 + 拒绝文案，是结论不是等待；窗口未起则纯由启动方报错，标题栏不画 |

注：Hello 未登记回落这一子情形，「建议登记 Hello」的引导只出现在 `get_status` 的 `helloHint` 枚举字段里，标题栏**不渲染**任何引导文案，弱门禁标注与正常 `system-credential` 完全一致。§4.1 三档只描述**身份门禁**；机器策略拒绝（含 fail-closed 缺失）不是门禁问题，一律走 §4 的 `blocked` 态，**不得**映射进任何门禁档位。

短标注跟在主文案后，间隔 1 个空格，字号同状态文案、颜色用 `status.text` 弱化一档（`none` 档用 `state.disconnected` 红点 + 主文案色，不弱化）；档位字段须带 test id `titlebar-gate-tier`，断言值覆盖三个枚举。

### 4.2 弱门禁标注（`system-credential` 专属）—— v1.6 作废

**作废**：A 类实测定案后，`system-credential` 已升格为「子会话系统登录验证」（窗口内系统登录界面，强验证），「未启用强验证」的弱标注场景不复存在。契约 v2.6 将 `gateStrength` 枚举值改为 `"login"`（原 `"session-only"` 作废）；**无论 `gateStrength` 取何值，标题栏 ready 态一律「仅绿点、无追加文案」**，`titlebar-gate-strength-note` 相关断言随本节一并废弃，UI 测试只保留 `titlebar-gate-tier` 三枚举断言。

## 5. 关闭二次确认

- 触发路径统一：标题栏 ✕、Alt+F4、任务栏右键"关闭"、系统菜单"关闭"，四条路进同一个确认流程。
- 形式：**系统模态对话框**（`MessageBox` 风格、挂在本窗口上、`Topmost` 仅对该窗口模态），禁止自绘轻量 toast 或内嵌确认条。
- 按钮顺序（Win 惯例，右对齐）：`取消`（默认，Enter 命中）、`结束会话`（destructive）。
- 图标：警告图标；标题：`结束会话？`。
- 正文（严肃警告，逐字定死，含"立即"与"不可撤销"）：`将立即结束当前会话并注销虚拟桌面，未保存的工作将丢失且不可撤销。`（单段，不堆详情）
- 已确认：关闭确认 = **立即注销**子会话；子会话内登录支持**微软账户 + Windows Hello PIN 快捷登录**（属 Windows/RDP 原生界面行为，与 §4.1 的开工门禁档位是两回事，文案互不混用）。
- Esc 与 `取消` 等价；点 ✕ 等价于 `取消`（关窗不级联二次弹窗）。
- `结束会话` 点击后：进入 `closing` 态（§4），执行注销与释放锁；任何一步失败，对话框关闭并由标题栏状态 + 错误日志报告，**退出码不得为 0 掩盖残留**（与规划方的清理规格对齐）。
- 确认框内的按钮命中区 ≥ 44px 高，字号 12px，遵循同套深浅色 token。
- **配置纯结构化（v1.2）**：确认框的全部内容抽成一个纯配置结构（标题、正文逐字、默认按钮、按钮顺序与标签、图标类型、Esc 语义），生产注入 `TaskDialogIndirect` 真系统模态框，回调 `Func<bool>` 仅作测试缝保留；UI 测试对**配置结构**做数值断言（默认按钮 == 取消、正文与 §5 逐字一致、destructive 在右），「点一下 / 按 Esc」的行为由验收方真机实测确认一次。

## 6. 实现要点（给实现方的交接，非视觉项）

1. DWM：启用 `DWMWA_USE_IMMERSIVE_DARK_MODE`（深色主题时）+ `DwmExtendFrameIntoClientArea(margins 0,0,0,1)` 只延伸底部描边，标题区走 `WM_NCPAINT` 自绘或 `WM_NCHITTEST` 命中 + 客户区上部自绘（实现选其一，验收只看 §1–§5 的可视结果）。
2. 命中：`WM_NCHITTEST` 按 §6.8 优先级返回——三键热区返回 `HTMINBUTTON` / `HTMAXBUTTON` / `HTCLOSE`（系统码，最大化按钮据此获得 Snap Layouts）；缩放边/角返回对应 `HT*`；标题条其余区域返回 `HTCAPTION`（系统给拖动与双击最大化）；其余客户区返回 `HTCLIENT`。由于窗口 `WM_NCCALCSIZE` 返回 0、没有非客户区，默认窗口过程无法完成非客户区按钮的按压周期，**三键的按下态、抬起判定与动作由窗口自己执行**（最大化/最小化走 `WM_SYSCOMMAND`，关闭走 `WM_CLOSE`）。
3. **Snap Layouts 面板：按官方指南实现并已由用户实测确认可用**。`WM_NCHITTEST` 对最大化按钮返回 `HTMAXBUTTON`，与 Microsoft 对自绘标题栏 Win32 应用的要求一致，悬停时由系统弹出布局面板。约束：窗口必须保持 `WS_MAXIMIZEBOX` 与 `WS_THICKFRAME`（`WS_OVERLAPPEDWINDOW` 已包含）、最大化态下按钮变为还原语义、按钮命中区必须覆盖实际按钮矩形。命中区口径（v1.2 修订，消除「46×32 却 ≥44px」的矛盾）：**按钮宽 ≥44px 物理像素**（96 DPI 基准 46px，任意 ≥96 的 DPI 下不缩破 44），**按钮高 = 标题栏高**（96 DPI 32px，跟随 Windows 系统标题栏惯例，不强制 44）；Win+方向键的系统级 Snap 不受影响。
4. DPI：`WM_DPICHANGED` 重算 §2.1 全部尺寸；所有 token 尺寸 × `dpi/96`。
5. 标题栏状态字段必须带稳定 test id 供 UI 测试（如 `titlebar-status-dot`、`titlebar-caption-text`），UI 测试只按 test id 断言，不按可见文案。
6. 失焦绘制：`WM_NCACTIVATE` 失焦时用 §2.2 失焦列重绘，色点除外。
7. 最大化边界：`WM_GETMINMAXINFO` 用 `MonitorFromWindow` + `GetMonitorInfo` 的**工作区**（非显示器矩形）计算 `ptMaxSize` / `ptMaxPosition`，保证最大化后任务栏完整可见、窗口精确贴工作区四边。
8. 命中优先级：`WM_NCHITTEST` 判定顺序为 **三键（46×32 热区）→ 缩放边/角（`window.resize-border` 8px）→ 标题条 `HTCAPTION`**；按钮热区不得被标题条或边热区吞掉。最大化态边/角缩放自然失效（系统行为），标题条拖动仍可用，不得自绘拦截。**三键返回系统码后动作由系统执行**（`HTCLOSE` 走 `SC_CLOSE → WM_CLOSE`），因此关闭确认的唯一入口是**接管 `WM_CLOSE`**：实现必须接住 `WM_CLOSE` 弹确认框，确认后才进 §5 的关闭序列，**禁止**在三键点击处或自绘层直接开始关闭；确认前会话状态保持原状不变。
9. 圆角与阴影交给 DWM 原生，不自绘；`WS_OVERLAPPEDWINDOW` 样式保留，任务栏行为由系统保证。
10. `WM_NCCALCSIZE` 首帧问题（实测记录）：窗口创建时第一次 `WM_NCCALCSIZE` 在 `CreateWindowExW` 内部就发出、窗口尚未登记，此时返回 0 不一定立刻生效；窗口创建后必须补一次 `SetWindowPos(SWP_FRAMECHANGED)` 强制重算框架，客户区才真正占满全窗（实测 884→900 修复）。
